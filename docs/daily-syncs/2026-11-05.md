## C02 — account-scoped dispatch admission and accounting

Implemented on the existing `usage_events` table (no second source of truth):

- `lib/model-router/admission.ts`: one pure policy (`MISSING_ACCOUNT`, `LOCKDOWN`, `LOCAL_ONLY`,
  `TRIAL_NOT_ADMITTED`, `UNKNOWN_COST`, `PAID_NOT_ADMITTED`, `UNKNOWN_PRICE`, `SPEND_CAP_UNSET`,
  `SPEND_HARD_LIMIT`, `TOKEN_HARD_LIMIT`), plus `reserveDispatch` / `settleDispatch` / `holdDispatch` /
  `releaseDispatch` / `reconcileDispatch`. Reservation locks the user row (`SELECT … FOR UPDATE`),
  sums current-month settled usage and **all open holds regardless of month**, and commits before any
  network call. Settlement is single-use and account-scoped. A lost/timeout/cancel response becomes a
  `held` row that survives UTC rollover; only a proven pre-transport failure is released.
  Reconciliation is a read and never retries the external call.
- Paid dispatch stays blocked: it needs `WHINK_PAID_MODELS_ENABLED=true`, a known price and a positive
  `WHINK_MONTHLY_SPEND_MICROS`. A BYOK key, an unset cap or a zero cap never authorises spend.
- `lib/model-router/dispatch.ts`: `admittedCall` / `admittedChatOnce` / `admittedEmbed` /
  `reserveVoice` / `runAdmittedVoice`.
- Wired the real production paths: tool loop (each tool round + tools-unsupported stream fallback),
  worker `workerAsk`, auto-memory extraction, orchestrator debrief, tool postmortem, skills security
  review and committee votes, swarm planner and agent calls, change-request refinement, embeddings
  (remote embedding without an account now returns `null` instead of calling out), and both voice
  routes.
- Schema: additive migration `20261105070000_dispatch_admission` adds attempt key, purpose, state,
  cost class/price snapshot, micro-USD hold, uncertainty, period and settlement time, plus a unique
  `(userId, attemptKey)` and `(userId, state, periodStart)` index. Legacy rows stay `state=recorded`
  with a null key. `budgetState` now also counts open holds opened in earlier months.
- Chat route returns a visible `409` with the refusal code instead of a generic 502.

## C03 — saved order reaches real dispatch, before any side effect

- `lib/model-router/ordered-dispatch.ts` defines `OrderedCandidate`, `orderedFromPlan` and
  `fallbackMayContinue`. A failure continues only when nothing has been sent and no tool has run.
  Account-wide refusals (`MISSING_ACCOUNT`, `TOKEN_HARD_LIMIT`, `SPEND_HARD_LIMIT`, `DB_FAILURE`,
  `INVALID_BOUND`, `ATTEMPT_CONSUMED`) stop immediately; cancel stops; model-specific 401/402/429,
  timeout and policy refusals may try the next saved choice.
- The chat route now passes the whole policy-filtered auto order to `runToolLoop` as `modelOrder`
  (plus `handoffAfter` when the plan ends at a manual handoff), instead of collapsing to the first
  entry. Explicit per-request models stay a single candidate; they do not silently borrow the profile.
- The tool loop walks that order **only on the first inference**. Each attempt gets its own admission.
  After the first successful response the model is committed; later rounds never switch, and a failure
  after a tool has run or bytes have been sent becomes an error/hold, not a replay. A `ToolsUnsupportedError`
  may still move to another tool-capable candidate, or the existing plain-stream path for the last one.
- Per-candidate BYOK keys are resolved and attached to the order, so a cloud key is never sent to a
  local candidate and a local turn is never charged to a cloud key. Local-Only and lockdown filter the
  order instead of replacing it wholesale.
- One unset default: `localDefaultModel()` is used by `streamChat`, `chatOnce`, the chat route and the
  worker. `purposeModel(env, key)` gives extraction/debrief, swarm, refinement and postmortem one
  override rule; none of them falls back to the Founder's paid chat order. `pipelineModel()` still
  returns `null` when the skills pipeline is genuinely unconfigured.
- `planRoute` gained `needsStream`/`stream_unsupported`; the trial gate is checked before it so NVIDIA
  still reports `trial_evaluation_only`. Chat planning now declares `needsTools: true`.

## Boundaries and remaining gaps

- Reconciliation currently reports outstanding holds; automatic release after an operator-confirmed
  safe cutoff is deliberately not implemented.
- UI shows token holds; micro-USD holds are recorded but not yet broken out in the usage screen.
- Tool rounds are admitted and settled per round; a cancelled stream after delivery is held, not
  refunded. This is intentional until an idempotency/uncertainty design exists.
- Voice cloud paths now refuse without a configured price and cap; that is a behaviour change for any
  deployment that previously relied on a bare provider key.
