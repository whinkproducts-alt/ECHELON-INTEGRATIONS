## First end-to-end acceptance journeys
**J1 truthful local:** Founder approves a scoped harmless existing-agent task → durable queue → worker ACK + actual execution → result/ledger → real HOLO status. No false 'dispatched'.
**J2 Mac fully off:** Commit authorized schedule/task and encrypted allowed state → power Mac OFF → off-device worker processes/saves it → status and pending approval visible from another device → Mac returns and syncs exactly once. This is an **unconditional functional scope requirement**, with deployment blocked only by explicit authorization/resource constraints, never silent deferral.
**J3 escalation:** Local cannot satisfy quality → router logs reason → eligible cloud provider only with proper approved monetary/data scope → carries bounded context → records cost/result. If provider would charge under default zero-spend, show blocked and request Founder approval rather than spending.
**J4 organization:** Delegation and independent review use canonical identities across 326 agents, and permitted lessons are shared without disclosing sealed Founder data.
**J5 no drift:** A change to off-device execution, spending or OpenClaw boundary with no ADR/approval is blocked by governance checks, and tests verify it.

## Release blockers and reporting rules
A `NOT VERIFIED` condition cannot count as pass. If no safe external compute/storage can meet Mac-off requirements under current zero-new-spend policy, present a **transparent release blocker and costed choices**; don't claim 24/7, don't activate spending, and don't quietly remove the functionality from scope. Founder gets an explicit impact/decision record. Every implementation ticket maps to traceability CSV and includes rollback before work starts.
