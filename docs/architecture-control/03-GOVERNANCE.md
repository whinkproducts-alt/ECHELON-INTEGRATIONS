**v0.3 — Approved governance intent and scoped M0/M1 implementation authorization.** Infrastructure and external actions retain separate approval gates.

## 1. Non-negotiable Founder authority
- **No unauthorized money.** Standing direction: zero new expenditure until revenue (`FDR-010`). No paid model, hosting, subscriptions, API, storage, migration, delivery or credits with billable overages without a specific newer Founder approval that changes the budget. Configure a default **deny paid admission** across all entry points; measure charges, do not assume 'free tier' means guaranteed zero.
- Protect actions such as purchases, installs, roster mutation/activation, repository writes or deletion, deploys, messages, publications, external data transfers and accesses to sealed Founder intelligence. The approval's exact action, cost, content, recipient, expiry and bound hash govern.
- WHINK/MAMBA, Kill Team and Codex may challenge or recommend; none can mint permissions. Existing deterministic late-approval council is **not** independent agent voting, per audit.
- Organizational proactive thought and event/schedule execution remain permissible **within standing Founder-approved scopes**. 'All 326 available' does not mean unlimited autonomous external acts. Prefer agent reuse/retraining; never automatically grow 326 agents or 163 teams.
- Prioritize WHINK Predict and WHINK Pro first mission, but no marketing publication/spend automatically implied by a mission.

## 2. Mandatory current build vs deferred future
**In-scope NOW:** single-user, local-first hybrid execution, cloud escalation when warranted and authorized, **24/7 Mac-off operation**, remote persistent central memory, all 326 agents operationally available, transparent execution/HOLO, shared learning with private Founder data sealed, ChatGPT command centre (subject to connector feasibility), effective permissions, and zero unapproved spend.
**Deferred until separate decision:** white-label commercialization, multi-customer billing/branding, adding a new organization, swapping Ollama/model without benchmark proof, broad upstream OpenClaw replacement, unexplained third-party app dependencies. Deferral of white-label must never defer Mac-off availability.

## 3. Anti-drift change gates
Each ticket must identify: `FDR-IDs`, `REQ-ID`, exact scope, baseline version/hash, before-state/path:line evidence, change and exclusions, security/cost/privacy impact, acceptance test, rollback, implementer, independent reviewer and **Founder approval reference**. Reject expanded scopes and undocumented architectural substitutions. New ADR required for changing execution ownership, core memory authority, admission gate, agent roster, cloud provider class, OpenClaw integration boundary or always-on design. Git author names are not consent.

**Proposed repo enforcement:** version this pack in a `docs/architecture-control/` folder only after approval; link from the existing Codex instructions without overwriting unknown `AGENTS.md`/`CLAUDE.md`; use scoped PRs, branch protection, CODEOWNERS on governance boundaries, automated checks (schema/contract/security/status accuracy/budget/traceability), independent review and explicit Founder milestone acceptance. None of this is presently certified deployed.

## 4. Handling no-cost vs always-on feasibility
Off-device compute and cloud-hosted authoritative memory require external infrastructure, which **may incur unavoidable costs**. This is a real engineering feasibility question, **not** license to drop the requirement. Codex must search/test eligible existing infrastructure or no-incremental-cost options, estimate capacity, failure modes and full pricing, and submit a clear option trade-off. If none meets reliability+privacy+zero-spend, mark `BLOCKED_FINANCING/DEPLOYMENT` and ask Founder to approve a bounded exception or a different approach. Never quietly buy infrastructure or claim Mac-off success without proof.

## 5. Sensitive knowledge and independent review
Maintain scoped organization memory, sealed Founder intelligence, tool-boundary data minimization, audit of who saw what and why, and safe learning only from authorized records. Apply the same policies to background jobs, locally installed standalone runner, direct content-analysis model calls, upstream OpenClaw capabilities and off-device workers. A route that cannot enforce policy is disabled for protected/paid actions until remediated.

## 6. Stop conditions / truthful claims
Stop and report: no clear owner approval, unknown cost or billable overages, unsupported remote data sharing, missing sandbox/credential boundaries, audit discrepancy, untested model switch, uncommitted work at risk, no rollback, disk/memory unsafe to benchmark, or a change requiring a new design. Never claim `LIVE`, `TEAM DISPATCHED`, `24/7`, `ZERO COST`, `VERIFIED` or `AGENT WORK COMPLETED` without corresponding scoped evidence.

## 7. Approval precedent
The document set is a **DRAFT**, not an instruction to write files, run tests, connect Codex, change configurations or deploy. Founder approves (a) architecture baseline, (b) read-only reconciliation, (c) narrow implementation ticket, (d) any external/live test, (e) release. Prior user decisions specify requirements but are not blanket permission to spend or make protected changes.
