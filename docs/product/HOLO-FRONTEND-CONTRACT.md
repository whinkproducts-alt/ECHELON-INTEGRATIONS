Preserve and evolve current HOLO rather than generating a standard dashboard. Audit actual KAMSI components and the separate `Whink-Ultimate-UI`/ `holo-gestures` repos as reference. Preserve code/asset provenance and verify licences before reuse.

## Visual identity
Authoritative tokens come from existing HOLO implementation; preserve previously specified AgentNetwork colors where applicable: base `#070B12`, cyan `#4ff3ee`, brain-blue `#38B6FF`. Central living neural orb/brain with existing portrait asset if licensed/available, 15 verified directorate hubs (16 reference conflict unresolved). Ambient motion is not proof of operating work.

## Required animation behaviors
- Slow continuous hub orbit with stable selection and readable labels.
- Particle flow from actual authorized organizational task/activity events toward neural centre, bounded count/rate.
- Inward ripple on verified completed learning event, no invented knowledge absorption.
- Separate external-intelligence node beyond the orbit with distinct flow.
- Distinct memory-absorption effect on successful acknowledged memory commit; not the same regular particle traffic.
- Distinct visually comprehensible statuses for idle, queued, approved, working, waiting, failed, recovered, completed, offline, blocked-policy and blocked-cost.
- Executive WHINK and MAMBA peer presence without mandatory per-task animation or hierarchical bottlenecks.
- Actual command centre navigation, keyboard/mouse interaction, accessibility/reduced-motion controls, mobile-responsive read-only or control surfaces where feasible.
- Voice/gesture only when verified real input paths exist; otherwise mark unavailable, don't simulate.
- Respect MacBook Air M3/16GB and share budget with inference: throttle/pause background animation, optimize canvas render and prevent unbounded GPU load.

## Data truth contract
Render only authoritative persistent backend status for any live state; stale/offline/reconnecting explicitly labelled. Distinguish DEMO fixtures. No fake `TEAM DISPATCHED` or `learning` notifications. All meaningful buttons require real backed actions and verified permission outcomes. Include accessible task detail/receipt view; click-through to source of each activity.

## Frontend spec deliverables
Design tokens; sitemap and inventory of screens/components; animations table (name, trigger, source event, durations, easing, cancellation, reduced motion); component prop interfaces; data/event schema; responsiveness and performance measurements; acceptance tests, screenshots/recordings from actual builds. No unsupported promises of hand tracking or deployed voice.
